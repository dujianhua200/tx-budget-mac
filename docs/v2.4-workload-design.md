# v2.4.0 工作量页重构设计：表三/表四分页 + 底部关联区

## 1. 背景（用户 2026-10-23 原话拆解）

> “工作量就是表三，预览页表三甲乙丙、材料汇总变成表四材料、安装设备，都放在工作量的位置，排成一排，一页一页的可以点击，最下面应该再划出一部分区域，显示表三工作量当前要用到的仪器仪表、机械和主材，不然如何自动生成表四。可定制性要强，什么都可以修改，我发现现在这个软件我输入工作量不跟主材有关联。”

三个问题：

1. **命名与结构不对位**：工作量页右侧预览标签叫“材料汇总”，不对应真实报表名；预览只是右半边的小窗，不是正式分页。
2. **录入与关联脱节（核心）**：在表三甲录工程量时，看不见、摸不着该定额关联的主材/机械/仪表，表四像黑箱自动冒出来，用户无法理解来源、无法修改。
3. **可定制性**：关联（消耗量、增删、主材价）必须可改，不能只读展示。

## 2. 分页结构（工作量区 = 报表分页）

工作量页顶部一排分页标签（segmented），占满内容宽度，点击切页：

| 分页 | 内容 | 来源 | 可编辑性 |
|---|---|---|---|
| 表三甲 | 工程量清单（定额录入） | 现 WorkloadView 左侧 ProTable | **可编辑**（唯一录入页）：改数量/系数、删行、顶部加定额 |
| 表三乙 | 机械报表 | 引擎 `CalcResult.table3B`（WorkloadMachinesView） | 只读预览 |
| 表三丙 | 仪器仪表报表 | 引擎 `CalcResult.table3C`（WorkloadInstrumentsView） | 只读预览 |
| 表四材料 | 甲供（表四甲）/乙供（表四乙）材料表 + 备选材料启用 | 引擎 `table4A/table4B`（WorkloadMaterialsView 改名与分组调整） | 生成值只读；保留**工程级修正**（手动调整、本工程单价、备选启用，见 §2.1） |
| 安装设备 | 表四甲设备组 | 引擎 `table4Equip`（WorkloadEquipView） | 同表四材料（工程级修正可改） |

原“材料汇总”页的设备组移交“安装设备”页独占（原先两处重复展示），表四材料页只留甲供/乙供两组 + 备选区。

### 2.1 生成页只读原则与例外

生成页（表三乙/丙、表四材料、安装设备）的**库派生值只读**：每个数字必须能溯源到「表三甲某行工程量 × 某条关联的消耗量」。修改库数据（关联、消耗量、库价）只在源头进行：

- **底部关联区**（本行关联，见 §3）；
- **资料库页**（全方案库维护）。

例外是**工程级修正**，它们不是库数据、只作用于本工程，属既有能力，不回收，仍留在表四材料/安装设备页：

- 材料手动调整量（`project.materialAdjust`）；
- 本工程单价覆盖（`project.materialPriceOverrides`，覆盖库价仅对本工程）；
- 备选材料启用开关（`project.ruleOverrides`）。

每页顶部小字写明口径，例如表三乙页：“自动生成，只读。数据来自定额的机械关联：修改请在表三甲点选工作量后用底部关联区，或去资料库维护。”

## 3. 底部关联区（本版核心，位于表三甲页底部）

表三甲页改为纵向分栏（VSplitView，可拖动）：上 = 工程量清单，下 = 关联区（默认高约 250pt）。

### 3.1 展示内容

- 未选中行：引导文案“在表三甲点选一条工作量，这里显示它要用到的主材、机械、仪器仪表，并可直接修改。”
- 选中行：标题行显示定额编号、项目名称、本行工程量（数量 × 系数）；下方三组并排：
  - **主材**：名称、规格、单位、种类徽标（通用/变体/变体*/备选）、消耗量、合计数量、单价、合价；未建档材料有“未建档”徽标。
  - **机械**：名称、单位、消耗量、合计台班、单价（价目库）、合价。
  - **仪器仪表**：同机械。
- 面板顶部固定一行明示（吸取 v2.0.1 隐藏模式教训）：
  **“这里改的是当前方案「{方案名}」库的关联，对使用该方案的全部工程生效；只想改本工程请用表四页的工程级修正。”**

### 3.2 “实际生效”的判定 —— 与引擎同一口径

判定逻辑单点实现于 `Logic/WorkloadLinks.swift`，供面板组装与测试使用。
**引擎 `Calc.swift` 一字不改**（计算口径冻结）；等价性由对照测试钉死（§5）：
面板对同一样本工程逐行求和，必须与引擎表三乙/丙的台班数、表四的自动数量逐项相等。

逐条对照（左 = 引擎 `calcProject` 行为，右 = 面板本行口径）：

| 关联 | 引擎聚合口径 | 面板本行贡献 |
|---|---|---|
| 机械/仪表（quotaMachines/quotaInstruments） | 台班数 = Σ参与行(数量×系数) × 映射消耗量；价按 mcode 查价目库（后行覆盖先行） | 基数 = 本行数量 × 系数（本行参与时）；合计 = 基数 × 消耗量；价同左 |
| 主材·通用 | 自动量 = Σ参与行原始数量（**不乘系数**） × 规则消耗量 | 基数 = 本行原始数量（参与时） |
| 主材·变体 | 基数 = 同（定额, 变体名）参与行原始数量之和，变体名精确相等（行 variant 为 nil 按 ""） | 本行 variant 与规则 variant 精确相等时，基数 = 本行原始数量 |
| 主材·变体* | 引擎单独遍历**全部**工程量行：定额相同、数量 ≠ 0 且非 NaN、variant 以规则 variant 为前缀即累加（**不查系数/负数有效性**） | 同左逐行判定（负数行也计入，与引擎一致） |
| 主材·备选 | 仅当规则 id 在 `project.ruleOverrides` 中被启用时，基数同变体 | 面板列出本行命中的备选规则：未启用时灰显并标注“备选未启用”，合计按 0 计（不生效）；提供启用开关（写工程级 ruleOverrides，不写库） |
| 价格 | 表四单价 = 本工程覆盖价 ?? 材料库价；未建档 = 0 | 面板单价 = **材料库价**（priceExcl，按 名称+规格 命中）；合价 = 合计数量 × 库价。文档明示：若本工程在表四页设了覆盖价，表四合价以覆盖价为准 |
| 供货分组 | 材料库 supply 非空优先，否则用规则 supply | 面板按同口径给出 effectiveSupply 供展示 |

“参与行”判定（引擎工程量累加循环）：定额在库中存在、数量非 nil 且 > 0 且非 NaN、系数（nil 按 1）> 0 且非 NaN。不参与的行（孤儿/数量 0/无效）在面板标注原因，关联照常列出但合计按 0 计——与引擎贡献为 0 一致。

**关于 appliesTo 的实测结论**：`RuleRow.appliesTo`（适用工程）目前仅被存储与导入导出携带，**引擎不消费**（Electron 母版的“一号多材适用工程”语义未在 Swift 引擎落地）。面板判定以引擎为准、不引入 appliesTo 过滤；此事实记录在案，本版不顺带改引擎口径。

### 3.3 可编辑操作（写回当前工程所属方案的库）

写回目标方案 = 工程所属方案（`getProfile(db, project.profileId) ?? activeProfile(db)`，与计算取数同一方案），**不是**资料库页的“当前方案”编辑目标。全部经 `AppState.updateDb` 落盘并即时重算（表三乙/丙、表四页与面板合计同步变化）。

| 操作 | 写回 |
|---|---|
| 改消耗量（主材） | `libraries.rules[i].consumption` |
| 改消耗量（机械/仪表） | `libraries.quotaMachines[i].qty` / `quotaInstruments[i].qty` |
| 删关联 | 从对应关联表移除该行 |
| 加主材关联 | 材料库选材 → 选种类（通用 / 变体＝本行项目名称）→ 填消耗量 → 追加 `RuleRow`（supply/unit 取材料行，appliesTo="全"） |
| 加机械/仪表关联 | 价目库选行 → 填消耗量 → 追加 `QuotaMachineRow`/`QuotaInstrumentRow`（mcode/mname/unit 取价目行） |
| 改主材单价 | `libraries.materials` 命中行（名称+规格）的 `priceExcl` |
| 主材未建档时建档 | 追加 `MaterialRow`（名称/规格取规则，单位取规则 unit，supply 取规则 supply，价格由用户填）后再改价 |
| 备选启用/停用 | `project.ruleOverrides`（工程级，不写库） |

写回函数全部落在 `Logic/WorkloadLinks.swift`（纯函数，`inout LibrarySet`），视图只负责取方案下标后调用——保证 Linux 可测（Views 在 `#if os(macOS)` 内不参与 Linux 测试）。

### 3.4 选择状态

工程量清单 ProTable 增加可选回调 `onSelectionChange`（默认 nil，其他使用方零影响）；工作量页据此记录单选行 id。清单行字典 id 改为稳定回退 id（行 id 为空时用行序占位），仅用于选择解析，删除等既有行为不变。

## 4. 影响面

- `Views/WorkloadView.swift`：布局重构（分页置顶、表三甲纵向分栏、选择状态）；原右侧预览窗撤销，五页内容复用既有视图。
- `Views/WorkloadMaterialsView.swift`：改名表四材料、移除设备组、文案更新。
- `Views/WorkloadEquipViews.swift`：表三乙/丙加只读说明小字（内容不变）。
- `Views/ProTable.swift`：仅新增可选 `onSelectionChange` 回调。
- 新增 `Logic/WorkloadLinks.swift`、`Views/WorkloadLinksPanel.swift`。
- 不动：Engine、Export、Models、Persistence、数据格式、资料库页与补全/清理逻辑。
- 版本：`TXBudget.version` 2.3.0 → 2.4.0（PlaceholderTests 同步）。

## 5. 测试计划（基线 174，只增不减）

新增 `Tests/TXBudgetTests/WorkloadLinksTests.swift`：

1. **与引擎一致性**：构造含同定额多行、系数 ≠ 1、四种规则种类、备选启用/未启用、负数行、孤儿行的样本工程；断言面板逐行合计之和 == 引擎表三乙/丙台班数与表四自动数量（逐材料键）。
2. **组装正确性**：单行面板数据——合计 = 消耗量 × 基数（含系数差异：机械乘系数、主材通用不乘）、价格命中/未建档、备选未启用灰显标记。
3. **写回**：改消耗量/删关联/加关联/改主材价/建档后，重建 Libs 重跑引擎，断言表四/表三乙/丙相应数值随之变化或消失。
4. **真实数据端到端**：App 种子库 + TXL3-187 变体场景（工程量行 variant=“挂钩法架设架空光缆 平原 6芯”）：面板出现变体主材「光缆 GYTS_6芯」合计 = 1.007 × 工程量、通用主材「铸塑光缆挂钩」合计 = 2000 × 工程量，且与引擎 `matQty` 相等；改变体规则消耗量后引擎数量同步变化。
