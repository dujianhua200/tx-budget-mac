## 3. 光缆主材单位：米，不是千米

**定位结论：错误在数据层。** 种子/用户库 `materials` 中
「光缆 GYTS_*/GYTA_*（18 行）、皮线光缆（1 行）」的 `unit` 写成“千米”；
引擎生成与界面显示都只是忠实取材料行 `unit`，无逻辑错误。
规则 `consumption = 1.007` 的语义是“千米/千米条”，与错误单位互相配套，
所以只改单位字符串会让生成量错 1000 倍，必须成对换算。

**修法（加载时一次性迁移，落在数据层、能真正修好用户现有数据）：**
- 纯函数 `migrateCableMaterialUnits(_ db: inout DbFile) -> Int`（Logic），
  由 `DatabaseStore.repair` 在每次加载时调用（repair 既有先例，迁移结果随
  下一次保存落盘）。
- 对每个方案库：`unit == "千米"` 的材料行 → `unit = "m"`（与内置完整库
  既有「光缆」行的单位一致，宇翔亦显示 m）；引用同一（名称|规格）的全部
  rules 行 `consumption × 1000`（1.007 → 1007 米/千米条）。价格不动
  （价格语义随单位由用户自理，与其“单位是米”的裁决一致）。
- 幂等：`MetaRecord` 新增可选字段 `appliedMigrations: [String]?`
  （容错解码，旧文件缺失 = nil），迁移后写入标记 `cable-unit-m-v26`；
  有标记则整体跳过——避免用户日后自建“千米”材料被误迁。
- 全库排查口径即“unit == 千米 的材料行”，种子内命中仅光缆/皮线光缆
  两类（19 行），无其他长度材料受影响。

## 5. 表四材料页重做（按宇翔表四甲截图格式）

**Bug 先查——结论：** 生成主材其实算得出（引擎 `table4A/4B` 有行、导出
表四正常），但 `WorkloadMaterialsView` 把 SwiftUI `Table` 塞进 `ScrollView`
的 VStack，Table 在滚动容器内高度塌陷，用户看不到行。且该页与全 App 的
ProTable 体系不一致。本版整页重做为 ProTable 平铺清单，结构性消除塌陷；
原“工程级修正”雏形（materialAdjust / materialPriceOverrides）并入下面
的统一工程级材料层，不留两套。

**列序（照截图）：** 代号 / 材料名称 / 规格程式 / 单位 / 数量 / 除税价格 /
材料金额 / 类型 / 类别 / 备注。甲供（表四甲）、乙供（表四乙）仍分两组两表，
安装设备页同组件按 supply=设备 渲染；导出结构不变（仍三组一表）。

**工程级材料层（数据设计，进引擎）：**
`Project` / `ProjectRecord` 新增三个向后兼容字段（缺失 = 空）：
- `materialEdits: [MaterialRowEdit]`——对生成行的覆盖，按生成行身份键
  `key = 名称|规格`（原键，改名不改键）定位：
  `code/name/spec/unit/supply/category/remark: String?` + `deleted: Bool`。
- `manualMaterials: [ManualMaterialRow]`——手工行全记录（id、code、name、
  spec、unit、qty、priceExcl、supply、category、remark）。
- `materialOrder: [String]`——行序（生成行原 key / 手工行 id 的全局序）。

`Calc.buildMatTable` 改为先生效行集再分组：
生成行（auto 数量 + 既有 delta 调整 + 既有单价覆盖）→ 套 `materialEdits`
（改名/规格/单位/类别/备注/代号、改 supply 归属、deleted 剔除）→ 并入
手工行（按自身 supply 入组、金额公式与生成行同：priceVat = 价 × 组税率）
→ 表内按 `materialOrder` 稳定排序（未列入者按生成序接末尾）→
totals 由生效行求和。于是取费（表二主材费）、表一、导出一律消费生效表四。
`Table4Row` 新增 `code/category/remark/supply/isManual`（默认值，源码兼容）；
导出表四的备注改为 `row.remark` 非空优先、否则按 `row.key` 查库备注
（与现行按 name|spec 查等价，改名后仍取原行备注）。

**可编辑性：** 除材料金额（= 数量 × 除税价，自动算）外全字段可改：
数量改 → 生成行写回 delta = 新量 − auto 量（沿用既有 materialAdjust 存储），
手工行直接改 qty；单价改 → 既有 materialPriceOverrides / 手工行 priceExcl；
类型列 = supply（select：甲供/乙供/设备，写 edit.supply 或手工行 supply）；
行可插入（onAdd 追加手工行）/删除（生成行写 deleted、手工行删记录）；
上移/下移写 materialOrder（见 §9）。不回写资料库。

## 7. 关闭工程功能

- 纯逻辑（Logic）：`projectSessionDirty(baseline:current:) -> Bool`——
  比较时忽略 `lastOpenedAt`（打开打戳）与 `updatedAt`（编辑副产物时间戳，
  真实内容变更必伴随其他字段变化），其余字段全等才算无改动。单测钉死。
- `AppState` 持 `openProjectBaseline`（打开/新建时在打戳后捕获）；
  `requestCloseProject()`：无改动直接关；有改动置提示态，视图弹三按钮：
  **保存并关闭**（flushSaves 落盘后关闭）/ **不保存**（把工程恢复为打开时
  基线后落盘关闭，即放弃本次打开后的全部修改，按钮文案明示）/ **取消**。
  关闭 = 清 openProjectId 与基线、nav 回工程列表。
- 入口：菜单栏新增「工程」菜单（关闭工程，无工程时禁用）+ 工作区工具栏
  「关闭工程」按钮（在“工程列表”旁）。

## 9. 表三/表四上下移动排序

- 表三甲：`project.quantities` 数组序即添加序（既有 append，无任何重排点），
  本版不新增排序；ProTable 新增可选 `onMoveRow(id, delta)` 回调，右键菜单
  出「上移/下移」，WorkloadView 接入纯函数 `moveQuantityRow`（按 dict id
  定位、与相邻行交换、边界 no-op；操作前给无 id 行补 id 落盘）。导出
  表三甲本就按工程行序分组，跟随自动生效。
- 表四：行上移/下移改写 `materialOrder`——纯函数以当前三组生效行的拼接序
  （甲→乙→设备）为全序基底，与相邻行交换后整表写回；新生成材料不在
  order 中，引擎按 §5 规则接在各组末尾，不冲已调顺序。
