# v2.2.0 设计：以官方 451 手册为准的定额库全面比对与校正

日期：2026-10-22。仓库 `dujianhua200/tx-budget-mac`，基线 v2.1.0（e6cc46e）。
范围：**数据校正 + 合并工具升级**。引擎计算口径、xlsx 导出、数据格式（LibrarySet 八表）一字不动。

## 1. 数据源与权威次序

| 数据 | 来源 | 定位 |
|---|---|---|
| 官方定额库 | 《通信451定额电子手册》v2022.12.716 单文件 HTML（用户 2026-10-22 提供，国家部门发布），留档 `scripts/data/official-451-manual-v2022.12.716.html` | **最高权威**：定额名称、单位、工日、材料/机械/仪表消耗量以它为准 |
| App 内置完整库（v2.1.0） | 小程序种子 `scripts/data/quota-data.js` 转换 | 被比对、被校正的对象；其台班价/材料价沿用（手册无价格） |
| 用户现有方案数据 | 用户数据库 | 合并时：key 命中内置库的行按官方校正；自建行与全部价格绝不触碰 |

## 2. 手册解析（`scripts/parse_official_manual.py` → `scripts/data/official-library.json`）

- 只认 `<table class="dTable">` 且含"定额编号"行的定额表（597 张，含续表；其余为表一~表五空白模板跳过）。按 rowspan/colspan 展开网格，值列 = 编号行各编码所在列。
- **名称重建**："项目"区多行表头按列自上而下拼接——整行横跨全部值列的单元格为公共片段，其余为该列片段；片段经 tight 处理（NFKC、去全部空白、剥 <sup> 脚注与 ①~⑳、ø/φ→Φ），片段间以单空格连接，与 App 现行风格一致（例：`挂钩法架设架空光缆 平原 36芯以下`）。经 12 条随机+指定抽查与原文逐项对照无误（TXL3-187、TSY3-055~057、TGD2-112、T5G3-038 等）。
- **拆分续表**：85 条定额被手册拆成两张表（材料过多分页），按编码合并：字段取非空、关联按名称并集，冲突记存疑保留先行值（实际 0 冲突）。
- **数值口径**（手册总说明十三：带括号表示的消耗量系供设计选用；"＊"由设计确定其用量）：
  - 纯数字 → 数值；`＊`/`(*)` → star（设计选用，无定值）；`(数字)` → 数值 + paren 标记（设计选用参考值，保留数值）；
  - 空/`—` → 无此项；人工行记 0 工日；
  - 多值写法（`28.28/2.02`、`(11.11/1.01)`、`102.50/103.00`、`(1.02/根横木)`，共 18 处）→ 无法唯一确定，记 `rawProblem` 入存疑清单，**不臆造**，校正时沿用现值。
- **源文件笔误**：全文 1 处闭合标签误写 `</td2>`（TSY3-056 技工 2.00 单元格），解析前统一还原并在报告计数，否则该格静默丢失。
- 解析自检（`scripts/data/official-parse-report.json`）：唯一编码 3,091，分册 TSD 340 / TSY 372 / TSW 651 / TXL 877 / TGD 324 / T5G 527，与手册分册计数逐一对上；无人工缺失；存疑仅上述 18 处。

## 3. 比对（`scripts/diff_official.py` → `docs/v2.2-official-diff-report.md` + `scripts/data/official-diff.json`）

### 3.1 名称归一化（比对与校正匹配共用）
`norm(s)` = NFKC → 去全部空白 → ø/φ→Φ → 波浪线/长破折号（~/～/—）统一为 `-`。
归一化后相等者记"写法差异"（不算错误）；App 名称以官方名称为前缀/后缀者记"前缀/上下文型差异"（小程序多加"安装/组立"或工作内容前缀）；其余记"实质差异"。

### 3.2 比对维度
覆盖（编码级）、工日（技工/普工逐条）、名称/单位（定额）、关联（材料/机械/仪表按定额+归一化名称比对缺失/额外/数量/单位；材料同名多规格行首行比数量、余行计额外规格行；官方 star 与 App 0 视为一致；paren 按数值比；rawProblem 不比数量单列沿用）。

### 3.3 核心结论（详见差异报告）
- 覆盖：官方 3,091 条全部在 App 库中；App 多 1 条 **TGD2-161**（官方编号自 160 跳号，无 161/162；该条为"砖砌通道人孔口圈部分"，属手册外子目，保留）。
- 工日仅 **3 条**不符（T5G3-022、TSD3-025、TXL5-053）——小程序工日数据基本可靠。
- 名称差异 1,146 条：写法差异 288（归一化后相等，含范围符号口径）、前缀/上下文型 541（小程序多加"安装/组立"或工作内容前缀）、实质差异 317（小程序截断/重复/错字/规格错位，如 T5G3-038 塔高分组错位、T5G3-235 名称截断）——以官方为准全数校正。
- 单位差异 93 条（如"每增"类单位 台→五块/五十盒、m3→百平方米），以官方为准。
- 关联：材料缺失 1,308 / 额外 790 / 量差 158 / 单位差 39；机械缺失 984 / 额外 1,033 / 量差 13；仪表缺失 293 / 额外 282 / 量差 10。典型：TGD2-112~116 镀锌钢管消耗小程序差约 30 倍；T5G1 一批定额仪表被小程序替换成别的仪表；TXL4-026 气体检测仪 0.4→0.3。

## 4. 校正后的内置库（`scripts/build_corrected_library.py` → 覆写 `Resources/full-library.json`）

以 v2.1.0 内置库为底、官方库为标准重建，重跑逐字节一致：
- **定额**：共同编码的名称/单位/技工/普工 := 官方；book/alias/coef 沿用现值；TGD2-161 等手册外定额整行保留不动；官方独有编码（本次 0 条）按官方新增（book 取手册册名、alias 取前缀、coef=1）。
- **关联（共同定额）**：整组按官方重建——
  - 材料→rules：consumption = star 时 0、其余官方数值；rawProblem 行保留现行同名规则原值（无现行则不建行，计数入构建报告）；unit := 官方；spec/supply 继承同定额同名现行规则（优先 spec 为空行），无则 spec=""、supply=甲供；remark：star → `设计选用`，paren → `设计选用(手册括号值)`，其余 ""；kind="通用"、variant=""、appliesTo="全"（沿用 v2.1 引擎语义裁决）。
  - 机械/仪表→quotaMachines/quotaInstruments：mname/unit := 官方；qty 同材料口径（star→0，paren 保留数值）；mcode 优先继承同定额同名现行关联的编码，否则按 v2.1 的名称→编码解析表（小程序价目 + App 现行价目，归一化唯一命中）解析，再无则空码保留。
  - 现行关联中官方没有的行（额外关联、多余规格行）**从内置库移除**（计数入构建报告）；手册外定额的关联整组保留。
- **materials**：现行条目保留（价格全 0 不在校正范围）；被校正规则引用而缺失的 (name, spec) 补入（priceExcl=0、supply 随规则）；若现行条目与校正规则同 (归一化名, spec) 而写法不同，条目名改写为官方写法（保持"规则名=材料名"可查价，价格字段不动），计数入构建报告。同 (归一化名, spec) 的双写法条目（如"石棉水泥板（δ10）"与"石棉水泥板 δ10"）去重只留首条——实测 4 组，价格均为 0；不去重会让 App 合并在两个写法间改名振荡、破坏幂等。
- **构建结果（实测）**：定额校正 1,183 条（名称/单位/工日任一变化）；关联重建 材料 6,613 + 存疑沿用 18、移除额外 材料 790 / 机械 1,033 / 仪表 282；materials 591 → 668（新增 81、改名 160、去重 4）；空码关联 机械 77 / 仪表 10（官方有此台班、名称解析不到唯一编码，保留空码不臆造）；台班价两表与全部价格逐字不变；构建脚本重跑逐字节一致。
- **台班价（machinePrices/instrumentPrices）**：整表沿用现值，一字不动（手册无价格）。

## 5. 合并升级："补全并校正"（`Logic/LibraryCompletion.swift`）

`mergeLibraryCompletion(base:full:)` 在原"只增不改"之上增加**校正**，总流程：先校正、后补全（补全逻辑与判定键与 v2.1 一致，含孤儿跳过；唯一补充见下条防重复规则）。

### 5.1 校正范围（key 命中内置库才校正）
| 表 | 判定键 | 校正字段 | 不校正 |
|---|---|---|---|
| quotas | code | name、unit、tech、labor | book、alias、coef、id |
| rules | (quota, norm(material), spec)，且仅 base 行为 kind="通用" | consumption、unit、material（改写为内置库写法） | kind、variant、appliesTo、supply、remark、id |
| quotaMachines / quotaInstruments | mcode 非空：(quota, mcode)；空码：(quota, norm(mname)) | qty、unit、mname | mcode 本身、id |

> 防重复补充（实现时定）：校正后内置库中原空码关联有 511 条补上了编码（机械 349、仪表 162）。合并时若 base 仍有同定额同名的空码行，按 v2.1 编码键会把同一台班重复追加、造成表三双计。故补全段对机械/仪表关联的“已存在”判定 = 编码键命中 **或** (quota, norm(mname)) 名称键命中；校正段对空码行亦按名称键命中 full 行校正数量。材料关联/材料条目因校正段先把 base 行名对齐官方写法，精确键即可命中，无此问题。
| materials | (norm(name), spec) 且由上条规则改名触发 | name（同步改写为官方写法，保持查价关联） | priceExcl、supply、unit、remark、id |
| machinePrices / instrumentPrices | — | **整表不校正** | 全部字段 |

- key 不在内置库的 base 行 = 用户自建行，**绝不触碰**（含其工日、消耗）。
- 计数：按行计（任一字段被改即计 1）：quotasCorrected / rulesCorrected / quotaMachinesCorrected / quotaInstrumentsCorrected / materialsRenamed；totalCorrected 为前四项 + 改名之和。
- 幂等：对已校正结果再跑，补全与校正计数必为 0。
- 匹配归一化（Swift 侧 `libraryMatchNorm`）：widthInsensitive 折叠（全半角）→ 去全部空白 → ø/φ→Φ → ~/～/— 统一为 `-`，与 §3.1 同口径。

### 5.2 UI（资料库页，`LibrariesView`）
- 按钮改名"补全并校正定额库"；确认弹窗必须写明："将按官方 451 手册校正定额工日与消耗量，你自建的定额和全部价格不动"，并预告补全 +N / 校正 +M（试算得出）；
- 完成报告分开列"补全 +N 条"与"校正 +M 条"明细；无补全无校正时提示"已与官方手册一致"。
